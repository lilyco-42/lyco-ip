# LYCO · 生图模型评价与生产管线选择

> 基于本项目的实测经验（2026-09/10）。
> **结论先行：不是模型不行，是这个任务超出了「文生图模型」的能力边界。**

---

## 一、逐模型评价

| 模型 | 指令遵循 | 参考图遵循 | 过拟合/加戏 | 判定 |
|---|---|---|---|---|
| **GPT**（gpt-image-2 系） | ★★★★ | ★★★ | 低 | ✅ **概念探索首选** |
| **豆包**（Doubao） | ★★★ | ★★ | 中 | ✅ **风格图 / 氛围图** |
| **Gemini**（nano-banana 系） | ★★★ | ★★★ | **高** | ❌ **违反 R1–R9** |
| **智谱清言**（ChatGLM） | ★★ | ★★ | 中 | ❌ 需求理解弱 |
| **workbuddy hy4** | ★★ | ★★ | 中 | ❌ |
| **Qwen**（图像应用） | — | — | — | ❌ |

### 各自的真实强项与失效点

**GPT —— 强在「听话」**
能读懂否定指令（「不要徽章」「不要文字」「要半垂眼」）。
这是它在本项目里唯一不可替代的能力：**R1–R9 是九条否定规则**，只有它大体遵守。

**豆包 —— 强在「好看」**
二次元审美讨喜，中文语义理解好。
**但读参考图确实失效**——实测把「黑发 + 红内层」的 Lyco 画成了**银白长发**。
它适合做「氛围图 / 风格探索」，不适合做「遵循设计」。

**Gemini —— 问题不是"降智"，是"过度自信"**
它会用训练集里的「华丽军装」先验**覆盖**你的人设，自动加金饰、加纹章、加装饰边。
**这恰好是 R2 明确禁止的**（无徽章/肩章/勋章）。
→ 在本项目里**不可用**。

**智谱清言 / workbuddy hy4 —— 需求理解弱**
「不通人性」的本质是：它们把需求当成"画个好看的图"，而不是"满足一份规格书"。

**Qwen —— 本项目实测不可用。**

---

## 二、真正的病根：没有模型「认识」她

以下三个原因是**结构性的**，和换哪个模型无关：

| # | 原因 | 说明 |
|---|---|---|
| 1 | **无先验** | Lyco 是原创角色，模型训练集里没有她 |
| 2 | **参考图带宽不足** | 一张参考图的约束力，**远小于**模型「二次元黑军装少女」这个强先验 |
| 3 | **几何不匹配** | 模型输出自由构图；而 Minecraft 要 64×64 固定 UV，Spine 要碎片矩形 |

**所以「不遵循人设」不是 bug，是必然。**
换模型只能换一种失败方式：**GPT 失败得安静，Gemini 失败得华丽。**

---

## 三、唯一真正的解法：训一个角色 LoRA

**这一步做完，「不遵循人设」这个问题就消失了。**

| 项目 | 说明 |
|---|---|
| 素材 | 20–30 张多角度图 —— 本项目**已有 14+ 张**（三视图 / 立绘 / Q版9姿势 / 表情 / 动作 / 武器） |
| 成本 | 消费级显卡约 30 分钟 |
| 效果 | 之后**任何管线**都认识她，且**不依赖聊天 App** |
| 产出 | `lyco.safetensors` → 放进 ComfyUI / WebUI 即用 |

**素材准备注意**：
- 必须是**多角度**（正/侧/背），否则 LoRA 只会画一个朝向
- 必须**背景干净**（纯白或透明），否则会把背景学进去
- 避免同一姿势重复太多

## 四、工具链的正确形态

```
❌ 现状：在聊天 App 里说「画一个 Lyco」
        → 一次性尽力而为，不可复现，不可调参

✅ 应该：ComfyUI 管线
         ├── LoRA(Lyco)           → 锁定身份
         ├── ControlNet OpenPose  → 锁定姿势
         ├── ControlNet Lineart   → 锁定轮廓（可直接描三视图）
         └── 固定 prompt + 调色板  → 锁定配色
```

**关键差别**：聊天 App 是「一次性尽力而为」，ComfyUI 管线是「**可复现、可调参、可控**」。
做的是**精密资产**，不是插画。

---

## 五、各类资产该用什么工具

| 资产 | 正确工具 | 现状 |
|---|---|---|
| 概念探索 | GPT / 豆包 | ✅ |
| 三视图（设计基准） | 人工 + 参考 | ✅ 已完成 |
| **精确资产**（MC 皮肤、游戏图集、图集带） | **代码** | ✅ 已验证 |
| 大批量同角色插画 | **LoRA + ComfyUI** | ⬜ 未做 |
| 直播待机动画 | Live2D 绑定（**不是生图**） | ⬜ 未做 |
| 3D 模型 | 建模 + 重定向（**不是生图**） | ⬜ 未做 |

### ★ 最重要的一条

**MC 皮肤、Spine 图集、像素资产属于「精确资产」，本来就不该用生图。**

- 它们的输出是**固定几何**（64×64 UV / 碎片矩形），生图模型不产出固定几何
- 正确做法是**代码逐像素画**（`tools/build_mc_skin_v2.py` 已验证）
- 之前在这类资产上「卡住」，是**路线选错了**，不是模型不行

## 六、给合作方的选型建议

| 场景 | 推荐 | 理由 |
|---|---|---|
| 快速看设计方向 | **GPT** | 最听话，能守 R1–R9 |
| 要好看的氛围图 | **豆包** | 二次元审美好 |
| 要严格遵循人设 | **LoRA + ComfyUI** | 唯一可靠方案 |
| 要精确几何资产 | **写代码** | 生图做不到 |
| 要动画 | **Live2D / 骨骼动画** | 生图做不到 |

**不要用**：Gemini（加戏）、智谱清言 / workbuddy hy4 / Qwen（需求理解弱）。

## 七、实测记录

| 现象 | 说明 |
|---|---|
| 豆包把黑发 Lyco 画成银白长发 | 参考图遵循失效的典型 |
| Gemini 自动加金饰 / 纹章 | 违反 R2 |
| 某会话 AI 得出「骨骼系统不能整张贴」 | **该结论正确** —— Spine 图集是碎片拼贴，只能按 UV 矩形逐片替换 |
| 生图产出的「皮肤图集」无法直接导入 | 它是示意排版，不是 64×64 UV 图集 |
