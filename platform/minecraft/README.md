## v3 逐条落实的约束

### 来自皮肤规范

| 约束 | 落实 | 自检结果 |
|---|---|---|
| 尺寸 64×64、RGBA | — | ✅ |
| **第一层必须完全不透明** | 逐面绘制，无留空 | ✅ 36 面全不透明 |
| **第二层只在该有内容处有像素** | 帽层 55%、外套层 25%，其余全透明 | ✅ 总占比 20% |
| 脸 8×8 六段式布局 | 刘海3行 / 额头 / 上眼睑 / 瞳+高光 / 鼻下 / 下巴 | ✅ |
| 眼睛给 2 行、高光朝内 | `HeesseeH` + `HEWSSWEH` | ✅ |
| 不画眉毛 | — | ✅ |
| classic / slim 两版 | 手臂 4px / 3px，UV 各自正确 | ✅ |

### 来自人设

| 约束 | 落实 | 自检结果 |
|---|---|---|
| 配色比例 黑70/红20/白肤8/银2 | 大面积黑，红只做内衬与滚边 | ✅ **68/18/3/2** |
| 只用配色表里的色 | 19 种色全部来自 `02-palette.md` | ✅ 无越界色 |
| 红是「从缝里透出来的」 | 红只出现在：裙下缘内衬、袖口 1 行、靴扣带、鞋底、发梢 | ✅ |
| 白 X 发夹在角色右侧刘海 | 图像左侧 col1/col2，放**外层**（主层会被盖住） | ✅ 2 白像素 |
| 滚边要克制 | 袖口从 2 行收到 1 行 | ✅ |

### 来自识别锚点

| 层级 | 锚点 | 落实 | 自检 |
|---|---|---|---|
| **L1 剪影** | 不对称裙长片**永远在她右侧**（图像左侧） | 裙下摆图左 2 行红、图右 1 行，形成斜切 | ✅ 图左红 8px vs 图右 2px |
| **L2 色块** | 上黑下红 | 上身高黑，红从裙下缘与鞋底透出 | ✅ |
| **L3 细节** | 白色 X 发夹，**3–7px 降级为白色斜向短划** | 8×8 脸上用 2px 对角线（不是完整的 X） | ✅ |
| **L4 动态** | 红色锐利残影 | 静态皮肤表达不了 → 交给动画 | — |
| **L5 行为** | 上半身静止 | 同上 | — |

> **L3 的降级规则是这次的关键**：8×8 的脸只有约 2–3px 能放发夹，
> 按 `07-recognition-anchors.md` 的规定应降级为**白色斜向短划**，而不是硬塞一个 X。
> 硬塞的结果就是之前那种"糊成一坨"。

## 自检输出（可复现）

运行 `python tools/build_mc_skin_v3.py`：

```
[slim] -> LYCO_mc_skin_v3_slim.png
     尺寸/模式      : (64, 64) RGBA  ✅
     第一层 36 面    : ✅ 全部不透明
     第二层占比      : hat=55%✓ jacket=25%✓ 其余 0%   总占比 20% ✅
     调色板          : 19 种色  ✅ 全部来自配色表
     配色比例        : 黑 68% / 红 18% / 白肤 3% / 银 2%   (人设目标 70/20/8/2)
     L3 X发夹(外层)  : 白像素 2 个 ✅
     L1 不对称裙     : 图左红 8 px vs 图右红 2 px  ✅ 左长右短
     → ✅ 全部通过
```

### 关于「白肤 3%」达不到 8%

人设的 8% 是**立绘里的视觉占比**。但在皮肤贴图里，**脸固定只有 8×8 像素**，
加上两只手 2 行，结构上最高也就 3% 左右。

**这不是缺陷，是媒介限制。** 强行加肤只会让画面变花。

## 已知限制

- **L4 / L5 锚点在静态皮肤里无法表达**（红色残影、静止的上半身）—— 需要动画
- **武器带不进皮肤** —— Minecraft 里武器是独立物品，不在皮肤上
- 8×8 的脸**物理上装不下**更多五官，这是所有 64×64 皮肤的共同上限
